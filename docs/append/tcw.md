# Interpretation of the campus network

> The ID.com client's authentication messages are classified as log-in, maintenance online and write-off, with physical addresses of machines, user names, passwords, etc., and include bound IP addresses; the message's configuration is uncontrollable, as part of the physical address binding guarantee that all subnet IPs will be sent when using the campus network client, and if we connect routers or use the computer's WiFi sharing function, the subnet IP will reveal what we did and the server will turn the client off.

> After some time, the client sends to the server an online maintenance package, so when we use the global VPN, the package is routed to the offline, resulting in the server not receiving requests to maintain online on time.
