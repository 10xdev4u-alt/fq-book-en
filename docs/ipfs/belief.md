# Faith in going to the center network.

> Original language:[Faith in going to the center network.](https://www.kawabangga.com/posts/2226)Author:[Kavabanga!](https://www.kawabangga.com/)

In Silicon Valley, a decentrized network is mentioned: people no longer get resources from the network's central server, and the network's resources are on everyone's equipment.

I'm more in agreement with the Internet, where talent is a real user rather than a server. The Internet should be connected to people, not people and servers.

There are many problems with the current centralized network. ** For example, a review **, it is virtually impossible to discuss any political issues on a domestic network in China today, and there is a great deal of “deleted content” in domestic social media, such as knowledge and microblogging, which has lost much of the Internet. The Internet was born to share knowledge and communicate, and an ideal Internet should be free to publish anything and no resource would be removed. But the current Internet has taken the wrong path, and centralized networks have made it possible for governments or website owners to delete resources. But imagine if our network is distributed? If the network existed on a machine of any one person, nothing would be deleted and a single resource could have countless redundant backups. Git and Bt is a success story.[Deleting warehouse](https://github.com/shadowsocks/shadowsocks)But because Git is distributed, if a warehouse is popular enough, there will be countless forrks, official warehouses can be deleted, and the project will always exist. In addition, the decentralised network has inherent anonymity, with resources ranging from one computer to another, and the publisher conceals his identity easily, if anonymity is not guaranteed, and if freedom of expression is guaranteed?

** Security issues. ** First, security of documents. All storage media are viable, and the safest way to store is to put them on the clouds. It is not safe for individuals to store any redundant backups, such as a fire at home, which could damage all the disks. But if a document is stored encrypted by BT on someone else's equipment (or if a resource suitable for sharing is to be shared), many backups can be used free of charge, and it is largely impossible (there may be some risks, but is not the idea of the Internet? For website operators, a centralized (e.g., a web server) is always at risk of falling, with server access through a variety of loopholes, and the attackers basically own everything. If your business is big enough, there may be leverage to negotiate with the machine room or the operator, but for small and medium-sized businesses, people are ignoring you and cutting you off. But a distributed network does not exist, and if the network is good, you can get resources from your nearest node, which is equivalent to an invisible super-CDN.

** Save resources.** Cloud storage is expensive and bandwidth is expensive. A centralized network can't avoid sending all the traffic to one place and keeping the resources in one place, like Google currently maintains DC.[About $12 billion a year.](https://gigaom.com/2015/02/04/google-had-its-biggest-quarter-ever-for-data-center-spending-again/)And even though the article says,[Higher cost of personal storage](https://leonax.net/p/8267/zeronet-will-be-the-next-failure/)But don't forget, distributed storage is a free space! I think costs are certainly lower than centralized data centres.

At present, a number of decentrization projects have confirmed the distributional success: Bitcoin has proven the feasibility of removing the central server approval transactions, Git has demonstrated that distributed version control is reliable and low-cost, and that BT, although banned in many countries, still has a significant number of users in use and at a good pace.
