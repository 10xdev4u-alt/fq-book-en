## Cluster

### Cluster concept

Computer clusters work with a high degree of collaboration through a combination of loosely integrated computer software and/or hardware. In a sense, they can be considered a computer. Individual computers in cluster systems are commonly referred to as nodes and are usually connected through local area networks, but there are other possible ways of connecting. Cluster computers are usually used to improve the computational speed and/or reliability of individual computers. In general, cluster computers are much more expensive than individual computers, such as workstations or supercomputers.

For example, the operation of a single load is shared on multiple nodes of equipment for parallel processing, and after each node of equipment is processed, the results are aggregated and returned to the user, and the system processing capacity is significantly improved. There are general categories:

** High-availability clusters:** Generally, when one node of the cluster fails, the task will automatically shift to another normal node. It also refers to the possibility of offline maintenance of a node in the cluster, which does not affect the operation of the cluster as a whole.

** Load balanced clusters: ** Load balanced clusters are operated generally through one or more front-end load balancers and distributed to a back-end group of servers to achieve high performance and availability of the system as a whole.

** High Performance Calculating Clusters:** High Performance Calculating Clusters use different computational nodes that assign computational tasks to clusters to improve their computational capabilities and are therefore mainly applied in the field of scientific computation.


## Distribution

** Cluster:** Same business, deployed on multiple servers. Distribution: One business is split into several sub-businesses, or is itself a different business, deployed on different servers.

In short, the distribution is to improve efficiency by reducing the duration of individual assignments, while clusters are to improve efficiency by increasing the number of tasks performed in unit time. For example, for example, Xinjiang, with many visitors, he can make a cluster, with a balanced server in front, and a few servers in the back to do the same business, and if, when there is a business access, the response to which server the load is not so heavy, it will be done for which server, and one server will collapse and the other servers can top it. Each of the distributed nodes performs a different business, and one of the nodes collapses, and the business may fail.


## Load Balance

### Concept

As the volume of business increases, the number of accesses and data flows to the core parts of the existing network increases rapidly, and so does the processing capacity and computing intensity of the network, making it impossible to afford a single server equipment. In this case, if existing equipment were to be thrown away for substantial hardware upgrades, it would result in a waste of available resources and, if faced with the next increase in the volume of business, it would result in a high-cost investment for another hardware upgrade, and even a highly performing equipment would not meet the current demand for increased volume of business.

By setting up virtual servers IP (VIP), virtualizing the application resources of multiple real servers at the back end into a high-performance application server, using load-balanced algorithms, forwarding user requests to the back inline server, returning the response to the load balancer, and sending it back to the user, the load balancer conceals the inner network structure from Internet users and prevents direct access to the back-office (Inlinenet) server, making the server safer and preventing attacks on the core web anchor and running other port services. Also, the load balance equipment (software or hardware) will continuously check the application status on the server and automatically isolate the invalid application server, achieving a simple, expansive and reliable application solution that addresses the problem of inadequate handling, expansion and reliability of a single server.

System expansion can be divided into vertical (vertical) and horizontal (horizontal) expansion. Vertical expansion is the enhancement of server processing capacity from a single machine perspective through increased hardware processing capacity such as CPU processing capacity, memory capacity, diskette, etc., which does not meet the problems of large distributed systems (websites), large flows, high co-production, and big data. A horizontal expansion is therefore needed to meet the processing capacity of large web-based services through machine additions. For example, if one machine cannot be satisfied, two or more machines will be added to the machine to share the pressure of access.

** One of the most important applications of the load balance is the use of multiple servers to provide a single service**, which is sometimes referred to as a server farm. Usually, the load balance is used mainly for Web sites, large Internet Relay Chat networks, high-volume file download sites, NNTP (Network News Transport Products) services and DNS services. Load balancers are now also beginning to support database services, known as database load balancers.

The server load balance consists of three basic Feature: the load balance algorithm, the health check and the maintenance of the session, the three essential elements for ensuring a load balance for normal work. Other functions are some deepening over these three functions. We will now give specific information on the role and rationale of each function.

Users have direct access to the server address (perhaps with a different address on the firewall, but essentially one-on-one access) before the load balancing device is deployed. When a single server is unable to handle access by a large number of users due to lack of performance, consideration should be given to the use of multiple servers to provide services in a way that achieves load balance. The principle for the realization of load balancing devices is to map the addresses of multiple servers into an external service IP (commonly known as VIP, which can directly map the server IP to VIP addresses, or server IP:Port to VIP: Port, which can be examined in a different way, and at the end, the server port is different from the VIP port), a process that is invisible to the end of the user, who does not actually know whether the server is loaded, because they have access to a purpose IP, so that when the user has access to the load balancing device, how to distribute the user ' s access to the appropriate server is the work to be done by the load balancing device, specifically, the three main Features mentioned above.

### Load balance algorithm

Generally, load balancing devices support a variety of load balanced distribution strategies by default, such as:

** RoundRobin** circulates requests in consecutive order to each server. When one of the servers malfunctions, AX removes it from the sequence line and does not participate in the next round of inquiries until it returns to normal.

**Ratio ratio: ** A weighted value is allocated to each server, and this ratio is rooted in the distribution of user requests to each server. When one of the servers fails, AX removes it from the server queue and does not participate in the distribution of the next user request until it returns to normal.

**Priority: ** Gives priority to all servers, defines priority to each group, allocates user requests to the highest priority server group (in the same group, distributes user requests using pre-set questionnaires or ratio algorithms); AX sends the request to the sub-priority server group when all or specified number of servers in the highest priority level fail. In this way, the user is actually provided with a hot backup.

** Minimal number of connections (LeastConnect):** AX will record the number of connections on each server or service port, and the new connection will be passed to the least connected server. When one of the servers fails, AX removes it from the server queue and does not participate in the distribution of the next user request until it returns to normal.

**Fast Response time:** New connections to servers that respond most quickly. When one of the servers fails, AX removes it from the server queue and does not participate in the distribution of the next user request until it returns to normal.

**Hashi Algorithm (hash):** The source address of the client, the port, is used for the al Hashi operation, which is forwarded to a server for processing based on the results of the operation, and when one of the servers fails, it is taken out of the server queue and does not participate in the distribution of the next user request until it is back to normal.

** Based on content distribution of the package: ** For example, the URL of HTTP is judged, and if the URL contains an extension of .jpg, the package is forwarded to the specified server.

### Health screening

Health checks are used to check the availability of services open to servers. Load balancing equipment is typically equipped with various health screening methods such as Ping, TCP, UDP, HTTP, FTP, DNS, etc. Ping is a third-level health check-up for server IP connectivity, while TCP/UDP is a fourth-level health check-up for UP/DOWN, which is used to examine service ports more accurately, using a 7-floor health check, for example, to create a HTTP health check, Get a page back, and to check whether the page content contains a specified string, and if so, the service is UP, and if it does not contain or cannot be retrieved, the server's Web service is considered not available (DOWN). For example, the load balancing device is checked to 172.16.20.3. The 80 port on this server is for DoWN, and the load balancing device will not forward the back connection to the server, but rather to another server using algorithms. When you create a health check, you can set the interval and the number of attempts to check, such as a five-second interval and a three-second attempt, then the load balancing device initiates a health check every five seconds, and if the check fails, try three times, and if all three fail, mark the service as DoWN, then the server will still check the DoWN server every five seconds, and at some point the server will be relabelled as UP when it is found that the health check has been successful. The interval and number of attempts for health check-ups are based on a combination of the principle that they will have no operational impact and will not place a significant burden on load balancing equipment.

### Organisation

How to ensure that a user's two requests to forward to the same server require that the load balance device configuration session be maintained.

The sessions are used to maintain continuity and consistency in the sessions, which requires that the user ' s back-to-back access sessions be kept on a server for processing, as it is difficult to synchronize user access in real time between servers. For example, if a user accesses an e-commerce website and the user logs in with the first server, the user ' s move to purchase the goods is handled by the second server, which will not succeed in this purchase because it does not know the user ' s information. This situation requires that sessions be maintained and that all user operations be handled through the first server for success. Not all visits, of course, require a session to be maintained, such as servers that provide static pages, such as web news channels, and that each server has the same content, so there is no need to keep a session.

The vast majority of the load equilibrium products support two basic methods of maintaining the session: The source/end address session is maintained and the cookie session is also a more common method, such as Hash, URL Persist, but not all devices are supported. Based on different applications, different sessions should be configured to be maintained, otherwise the loads may be uneven or even unusual. Our main analysis of the B/S structure is to maintain the session.

For applications of the normal B/S structure, such as static pages of the website, any session can be maintained without any configuration, but for a business system based on the B/S structure, especially the intermediate platform, it is necessary to have a session maintained and, generally, we can meet the needs by configuration of the source address session, but in view of the fact that the client may have the above-mentioned environment that is not conducive to the maintenance of the source address session, it is a better way to use the Cookie session. ### Other benefits of load balance

** High expansion**

By adding or reducing the number of servers, high and simultaneous requests can be better responded to.

** (server) health check**

The load balancer is able to check the health status of the back-office server application and remove malfunctioning servers from the server pool to improve reliability.

**TCP Connection Reuse**

TCP-connection reuse technology is requested to reuse HTTP of multiple front-end clients to a TCP connection established by the server at the back-end. This technology can significantly reduce the server's performance load, reduce the delay associated with the new TCP connection to the server, and minimize requests for co-connections from the client to the back-end server and reduce the server's resource occupancy.

As a general rule, the client needs to make three TCP handshakes with the server before sending a HTTP request and then send a request. The server received HTTP requests for processing and sent the results back to the client, then the client and the server sent each other FIN and closed the connection upon receipt of FIN ACK confirmation. In this way, a simple HTTP request would require a dozen TCP data packages to be processed.

Following TCP connection to reuse, three handshakes between the client (e.g. ClitA) and the load balancing device were held and HTTP requests sent. Upon request, the load balancing device will test whether the server has an empty long connection and, if not, a new connection will be created. When the HTTP request is completed, the client closes the connection in consultation with the load balancing device, while the load balance maintains this connection with the server. When another client (e.g. ClearB) has to send a HTTP request, the load balancing device sends a HTTP request directly to this idle connection maintained between the server and avoids the delay and server resource consumption caused by the new TCP connection.

![](https://i.postimg.cc/8zTxL1vd/266.png)

In HTTP 1.1, the client can send multiple HTTP requests in a TCP connection, a technique called HTTP reuse. The most fundamental difference between it and the TCP connection is that the TCP connection is reuse of a multi-client HTTP request to a server-end TCP connection, while the HTTP is a client of multiple HTTP requests to be processed through a TCP connection. The former is a unique function of the load balancing device; the latter is a new feature supported by the HTTP 1.1 agreement and is currently supported by most browsers.

**HTTP Cache**

Load balancers can store static content and can respond directly to users when they request them without having to ask back-office servers.

** TCP buffer**

TCP buffers are intended to address the waste of server resources due to the mismatch between back-end server speed and client front-end network speed. The link between the client and the load balance has a higher time lag and lower bandwidth, while the load balance is connected to the server with a lower and high bandwidth LAN. Since the load balancers can temporarily save back-office server data on client responses and then forward them to customers with longer response times, the back-office Web server can release the corresponding threads for other tasks.

** SSL acceleration**

In general, HTTP transmits over the network in an explicit manner and may be subject to unlawful wiretapping, especially for authentication password information, etc. In order to avoid such security problems, SSL protocols (i.e. HTTPS) are generally used to encrypt HTTP protocols to ensure the security of the entire transmission process. In SSL communications, asymmetric key technology is used first to exchange authentication information and to exchange session keys between the server and browser for encryption data, and then to encrypt and decrypt information during the communication.

SSL is a safety technology that requires significant CPU resources. Currently, most load balancing devices use SSL acceleration chips (hardware load balancers) for SSL information processing. This approach provides a higher SSL processing performance than the traditional server-based SSL encryption, thus saving significant server resources and allowing the server to focus on the processing of business requests. In addition, the introduction of centralized SSL processing would also simplify the management of certificates and reduce the workload of day-to-day management.

** Content filter**

Some load balancers can modify their data through them as required.

** Invasion blocking function**

The security of the application layer is provided on the basis of firewalls to secure the network/transmitting layer.

The realization of the load balance is discussed below at different levels:

DNS is responsible for providing domain name resolution services, and when visiting a site, it is in fact necessary to first obtain the domain name point IP address through the DNS server, where the DNS server completes the mapping of the domain name to the IP address. Similarly, the mapping can be more than one-to-one, at which point the DNS server acts as a load-balanced scheduler, spreading user requests to multiple servers. The advantage of this technology is that it is simple, easy to implement, low-cost, applicable to most TCP/IP applications, and that the DNS server can find the nearest server to the user in all available A records. However, its shortcomings are clear, first, that this option is not a real load balance, and that the DNS server distributes the Http request evenly to the backstage Web server (or according to geographical location) without taking into account the current load of each Web server; if the configuration and processing capacity of the backstage Web server are different, the slowest Web server will become a bottleneck for the system and the most capable server will not be fully operational; and second, it does not consider a fault, and the DNS server will still assign the DNS request to the malfunctioning server, resulting in a failure to respond to the client. The last point is fatal and could result in a significant proportion of clients not benefiting from Web services, and the consequences would last for a considerable period of time (generally DNS has a replacement cycle of approximately 24 hours) due to the DNS cache. As a result, the latest Web site programme of the construction centre abroad has rarely been used.

**Technology layer (OSI level 4) load balance**

The transfer layer is OSI 4 and includes TCP and UDP. The popular transfer layer load balancers are HAProxy (which is also used for application layer load balance) and IPVS.

**Applied Layer (OSI 7th Layer) Load Balance**

The application layer is OSI 7th. It includes HTTP, HTTPS and WebSockets. A very popular and time-tested application layer load balancer is Nginx.

The so-called seven-storey load balance, also known as the “content exchange”, is the ultimate choice of internal servers, mainly by means of truly meaningful application layers in the message, plus the server selection method set by the load balance device. In common TCP, for example, if the load balance device is to select the server according to the actual application layer content, it can only establish a connection (three handshakes) between the final server and the client before seeing the message sent by the client about the true application layer content, and then determine the final choice of the internal server based on the selected field in the message, plus the server selection set by the load balance device. The load balancing device in this case is more like a proxy server. The load balance and front-end client and back-end servers will be connected to TCP, respectively. Thus, from this technical point of view, the seven-storey load balance is clearly more demanding for load balancing equipment, and the capacity to process the seven-storey would inevitably be lower than the deployment of the four-storey model. So why do we need a seven-layer load balance?

The advantage of a seven-layer load balance is to make the entire network more "smart," such as the one listed above, mostly based on seven-layer load balances. For example, user traffic to a website can be transmitted to a specific photo server in a seven-layer format and can use cache technology; requests to a text class can be forwarded to a specific text server and compression can be used. This is, of course, a small case of a seven-tiered application that, in technical terms, allows for arbitrary modifications to client requests and server responses, greatly enhancing the flexibility of the application system at the network level.

Another function often mentioned is security. The most common SYN Flood attack on the network, where hackers control numerous source clients and use false IP addresses to send SYN attacks against the same target, usually results in the mass delivery of SYN messages and the depletion of related resources on the server to achieve the objective of the Special of Service (DoS). Technically, it can also be seen that these SYN attacks under the four-story model are forwarded to the back end of the server, while the SYN attacks under the seven-story model naturally end on the load balancing device and do not affect the normal operation of the back-story server. In addition, load balancing devices can further enhance the overall security of the system at the application level by setting out a variety of strategies at the seven-level level to filter out specific messages, such as the application level of SQL Injection.

The current seven-layer load balance focuses mainly on the application of a wide range of HTTP protocols, so its application is mainly for B/S-based systems such as numerous websites or internal information platforms. The four-layer load balance corresponds to other TCP applications, such as ERP systems developed on the basis of C/S.
