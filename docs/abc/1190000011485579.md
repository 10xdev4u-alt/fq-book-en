## SSH Tunnel

SSH (Secure Shell) is a secure network agreement providing data communication security, remote login, remote command execution, etc., proposed by Tatu Ylönen, Researcher at the University of Helsinki, Finland, in 1995, to replace unsafe remote Shell protocols such as Telnet, rsh, Rexec, etc. SSH has since developed two large versions of SSH-1 and SSH-2.

If you want to know more about SSH, you can look at O'Rely.[SSH: The Security Shell - The Definite Guide](http://openyoudao.org/_media/ssh_second_edition.pdf)It's a very good book.

So let's see how simple it is to build a SSH tunnel over the wall. First of all, you need an off-wall server that supports SSH, and that doesn't need anything, as long as you can connect to SSH.

Client SSH performs the following command:

```text
ssh -D 7001 username@remote-host
```

In the above order -D indicates dynamic binding, 7001 means local SOCKS proxy's interception port, which can be changed to another, later`username@remote-host`It's the user name and host that you log in to the remote server. Of course, this command will prompt you to enter the password, which is the password of the user username (unless you have an SSH key authentication, you can not enter the password), so the tunnel is open.

Because ssh is based on[RSA encryption technology](https://zh.wikipedia.org/wiki/RSA%E5%8A%A0%E5%AF%86%E6%BC%94%E7%AE%97%E6%B3%95), the GFW is therefore unable to analyse the encrypted data content from the data transfer, avoiding the problem of re-linking, but because of the obvious characteristics of ssh itself during the creation of the tunnel and data transfer, the GFW once interfered by analysing the characteristics of the connection, leading to the problem of ssh being subject to targeted interference.

## VPN

Business networks are changing as the times and the size of enterprises grow. For example, a Beijing-based company may have branches in Shanghai, Guangzhou and Shenzhen, and there is a need to connect the branches in order to share resources, work together and work more efficiently. However, the traditional network of connections is expensive and generally unaffordable for SMEs. And then the low-cost VPN technology was born.`VPN (Virtual Private Network)`Name`Virtual private network`It can use low-cost public networks (mainly using Internet-nets) to transmit private data, which is more cost-effective than the traditional feeder approach and is therefore used by many businesses and telecommunications operators.

VPN is at the bottom of the shadows. It virtualizes a network adapter directly via an interface to the operating system, and the network communication of the entire operating system will be sent and sent via this virtual card. This is in line with the realization of any proxy, and the application level does not know that the network adapter is virtual, so that the Vpn virtual card will process the data as an intermediary, thus achieving all the magic effects. Specifically, vpn is a virtual network adapter driven by the development of a network adapter and registered to the operating system, so that data can be intercepted and processed as long as they are sent and sent through the card.

The difference between the VPN and SSH tunnels is as follows:

* The VPN set-up is global, i.e., once the computer has been attached to the VPN, all the networking programs will automatically use VPN; when the SSH tunnel is set up, it will be necessary to set the use of the tunnel before it is connected.
* If a commercial VPN is used, it usually costs money, and if it is built on its own, VPN is more difficult to build than the SSH tunnel. Because SSH Tunnels need only a server that can SSH, there is no need to configure anything on the server.
* vpn works on the IP level, while shadowsocks works on the TCP level.

## Distinction between the SS global model and the PAC model

The global model of Shadowsocks is to set up your system proxy proxy server to send all your http/socks data through the proxy server. Only software that supports socks 5 or uses system proxies can use Shadowsocks (general browsers are default system proxies).

And the PAC model is to read the rules in the PAC file when you connect to the website, to determine if the site you visit is walled, and if you do, you will use the proxy server to connect to the website, and the PAC list is usually updated from the GFWList. GFWList regularly updates the walled website (although it is generally slow).

In short, under the global model, all websites defaulted on the proxy. The PAC model, on the other hand, represents only the walled ones, recommends the PAC model, and if the PAC model does not have access to some websites, try to change the global model, usually because the PAC update is not timely (or possibly the GFWList update).
